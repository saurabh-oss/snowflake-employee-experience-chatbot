How it works

Three Cortex tools,
one conversational answer

Every question is classified by intent, routed to the right tool, and synthesised into a grounded, cited response — all inside Snowflake.

01

Cortex Search

Hybrid semantic + keyword retrieval over HR policies, handbooks, and KB articles. Finds the right paragraphs across thousands of documents in milliseconds.

Policy questions
02

Cortex Analyst

Translates natural language into governed SQL via a declarative semantic model — querying leave balances, ticket counts, attrition rates, and headcount data live.

Data questions
03

Cortex COMPLETE

An LLM synthesises retrieved policy text and query results into a single, concise, human-readable answer with cited sources — never fabricating data.

Capabilities

Built for enterprise
employee experience

Everything HR and IT teams need, governed at the data layer.

Leave & Time Off

Employees can instantly check leave balances, entitlements, carry-forward status, and pre-approved days. Data is filtered by the requesting employee's ID — no one can see someone else's balance.

Cortex Analyst + Row Policy

Policy & Compliance

Searches across Global Mobility, Annual Leave, Acceptable Use, and Code of Conduct policies using hybrid semantic + keyword retrieval. Returns the relevant paragraph with the policy name and section cited.

Cortex Search

IT Support

Employees can look up their open tickets, check resolution status, and raise new incidents. The chatbot uses the IT Acceptable Use Policy to suggest self-service fixes before escalating.

Cortex Search + Analyst

Manager Analytics

Managers get quarterly attrition rates, headcount trends, exit reason breakdowns, and comparison against org-wide averages — all filtered by their MANAGER_ID automatically.

Cortex Analyst + RBAC

Security & Governance

Governance that your
CISO will love

Built on Snowflake Horizon — the same access controls that protect your data also protect your AI queries.

1
Network isolation
PrivateLink / VPC · TLS 1.3 · IP allow-lists
2
Identity & access
RSA key-pair auth · SSO (SAML/OIDC) · MFA enforced
3
RBAC role hierarchy
ADMIN → APP → USER · Object-level grants per role
4
Data protection
Column masking (salary, email) · Row-access policies
5
AI governance
Cortex respects RBAC · No training on your data · Horizon Catalog lineage
6
Full audit trail
Every prompt, tool call, and retrieved row logged to AUDIT.INTERACTION_LOG
What "data stays in-perimeter" means
✓ No external model API calls. Cortex runs inference on Snowflake-managed GPUs in your region — your prompt never leaves.
✓ No model training on your data. Snowflake contractually prohibits using customer data to train models.
✓ Masking applies to AI queries. If salary is masked for a role, the LLM never sees the real value — it processes the masked result.
✓ Row policies filter AI context. Employees can only retrieve data they're authorised to see. The chatbot cannot bypass row-level restrictions.
✓ Every query is auditable. The interaction log captures the employee, question, tool calls, SQL generated, and latency — for compliance and debugging.
Quick start

Up and running
in under 30 minutes

Requires a Snowflake account (trial works), Python 3.10+, and Node.js 18+.

1
Run the Snowflake setup scripts in order
-- In Snowsight SQL Worksheet, run as ACCOUNTADMIN -- 01_setup_database.sql → database, roles, warehouses -- 02_create_tables_and_data.sql → employee data + masking -- 03_cortex_search.sql → policy search service -- Upload 04_semantic_model.yaml to @EX_CHATBOT.PUBLIC.SEMANTIC_MODELS -- 05_cortex_agent.sql → audit log
2
Generate key pair and configure the backend
# Generate RSA key pair openssl genrsa 2048 | openssl pkcs8 -topk8 -nocrypt -out snowflake_private_key.pem openssl rsa -in snowflake_private_key.pem -pubout -out snowflake_public_key.pem # Register public key in Snowsight -- ALTER USER YOU SET RSA_PUBLIC_KEY='<public-key-body>'; # Set up environment cp .env.example .env # then edit with your account + key path python -m venv .venv && .venv/Scripts/activate python -m pip install -r backend/requirements.txt
3
Start the backend and frontend
# Terminal 1 — Backend cd backend && python main.py # → http://localhost:8000/health {"status":"healthy"} # Terminal 2 — Frontend cd frontend echo "REACT_APP_API_URL=http://localhost:8000" > .env.local npm install && npm start # → http://localhost:3000
